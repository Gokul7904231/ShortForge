# ReMaker v2 — Surgical Repair Architecture

**Date:** 2026-10-02  
**Status:** IMPLEMENTED ON FEATURE BRANCH / PENDING MAINLINE VALIDATION

## Decision

ReMaker is a Level-1 surgical repair control plane. It decides the smallest authorized repair scope and delegates physical execution to the existing RenderFabric -> Compute Fabric path.

ReMaker is not:
- a second renderer;
- a publication authority;
- an F07 verifier;
- a capability-granting component;
- an upstream semantic author.

## Activation contract

A repair may activate only when all of the following are true:

1. F07 (or another authorized verifier) produced a repairable finding.
2. The repair has an explicit target that resolves to TimelineIR nodes or a concrete frame window.
3. The parent artifact is immutable, SHA-256 identified, CAS-bound and paired with the exact parent TimelineIR digest.
4. The repair carries a CAP_REMAKER_REPAIR grant, expiry and fencing token.
5. The requested action is present in the allowlist and absent from the forbidden set.
6. A bounded attempt/time budget exists.
7. A requested-change digest exists, making repair identity deterministic.

## Scope model

ReMaker separates:
- **logical repair target**: subtitle/audio/asset/timing/region nodes;
- **physical render scenes**: the visual scenes that must be rebuilt to materialize that change;
- **temporal context**: an explicit frame window with a small pre/post halo.

This prevents a subtitle/audio repair from being incorrectly treated as the same thing as its physical render window.

## Execution

The ReMaker engine:
1. validates the request;
2. computes deterministic impact;
3. creates an immutable repair plan and idempotency key;
4. calls an execution port;
5. requires a new physical artifact;
6. checks changed-node and preservation invariants;
7. bounds retries and detects no progress;
8. emits a repair receipt requiring F07 re-verification.

The execution adapter stamps the approved surgical scope and invokes RenderFabric. The Python renderer force-rebuilds only the named repair scenes while unrelated scenes remain content-addressed.

## Cache safety

Scene cache identity now serializes the full scene structure deterministically, including:
- narration;
- lock state;
- audio path;
- captions;
- shot timing;
- recipe;
- props;
- motion;
- assets.

This closes a stale-reuse hazard where a semantically changed scene could previously retain an old cache identity.

## Routing rule

Localized media/timeline repairs may enter ReMaker:
- asset replacement;
- localized sensitive-content reframe;
- duration/geometry repair;
- subtitle/audio/timing repair when future findings provide explicit target scope.

Semantic creative changes remain upstream:
- narrative restructuring;
- hook-family changes;
- originality changes;
- script rewrites.

## Stop conditions

ReMaker stops on:
- successful execution and handoff to F07;
- expired authorization;
- fencing loss;
- invalid/stale parent;
- invalid physical artifact;
- failed preservation invariant;
- no progress;
- execution failure;
- budget exhaustion;
- explicit escalation.

## Verification boundary

ReMaker never decides that its repair is correct. Its candidate is always returned to F07 for independent verification. Publication remains downstream of a successful F07 release decision.

## Research basis

The design was cross-checked against:
- Remotion frame-range rendering and partial-range composition;
- OpenTimelineIO time/range semantics;
- ComfyUI dependency-local partial execution and caching;
- VideoRepair localized evaluation/planning/decomposition/refinement;
- recent temporal-structure and localized video-editing work;
- C2PA derived-asset, ingredient and edit-action provenance;
- ShortForge's existing AgentTube-derived scene manifest/checkpoint/cache patterns.

## Deferred / experimental

Frame-level codec differential re-encoding with motion-vector reuse is intentionally not enabled as a production primitive yet. The current production-safe optimization is scene-local rebuild plus content-addressed reuse. Any future frame-level splice path must prove codec/keyframe safety and independent F07 physical verification first.

## Required promotion evidence

- ReMaker unit/contract tests;
- repository TypeScript CI;
- F04/F05/F06 render validation;
- F07 physical truth validation;
- authorization/fencing tests;
- surgical cache/rebuild proof;
- preservation and idempotency tests;
- no “production-ready” claim without physical artifact evidence.
