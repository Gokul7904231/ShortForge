## Evidence Tier Definitions:
- **IMPLEMENTED**: Code exists and compiles.
- **UNIT-VERIFIED**: Isolated behavior proved by meaningful tests.
- **INTEGRATION-VERIFIED**: Multiple real modules interact correctly.
- **E2E-VERIFIED**: Real application path works through multiple system layers.
- **REAL-SMOKE-VERIFIED**: Real process / filesystem / FFmpeg / worker execution verified.
- **PRODUCTION-VERIFIED**: Real third-party production interaction has been executed and evidenced.
- **SIMULATED**: Mock / fake / synthetic provider or response.
- **LEGACY**: Historical compatibility path not allowed to silently execute in production.
- **DEAD-CODE**: No valid production caller.
- **UNKNOWN**: Not sufficiently proven.

## 5. Summary of Defective Requirements Requiring Immediate P0/P1 Repair

1. **R003 / R001 / R002**: Elimination of placeholder `e3b0c44...` hash fallback, enforcing real physical byte hashing directly from CAS.
2. **R005 / R006**: Cryptographic trust store with static key ID validation and rotation support, fixing ephemeral key generation on restart.
3. **R007 / R008 / R009 / R039 / R040**: Durable SQLite authorization store with atomic SQL CAS updates (`UPDATE ... WHERE status = 'ACTIVE'`), surviving process restarts.
4. **R013 / R014 / R042**: Removal of fake social stubs (`social-platforms.ts`), enforcing fail-closed `AUTH_NOT_CONFIGURED` and mandatory `ReleaseAuthorization` across all platforms.
5. **R015 / R016**: YouTube Data API parameter fidelity (`containsSyntheticMedia`, preserving exact authorized title and tags without truncation or synthetic defaults).
6. **R021 / R023**: Policy-as-data lifecycle (hashing actual retrieved source bytes, date-aware snapshot selection instead of hardcoded `latest`).
7. **R025 / R034**: G05 structured rights evidence and G14 strict structured `EvidenceRef` validation.
8. **R037**: Artifact lineage DAG cycle rejection and restart persistence.
9. **R041**: API caller authentication on `POST /api/publish/queue` and `DELETE /api/publish/queue`.
