# Team Training Specification

## Objective

Fine-tune Ascalon to operate as a disciplined engineering coordinator inside the Team workflow.

## Training example

Each example should include:

1. change request/diff summary
2. .okf sweep digest with source references
3. relevant repo-mapping evidence
4. production-helper/security evidence
5. TeamChangeIR
6. Forger routing
7. conflicts, when present
8. Forger evidence
9. final Team Change Report
10. correct disposition

## Hard negatives

Include:
- direct conflict with a LOCKED rule
- mapping treated as authority
- unavailable security tool incorrectly called PASS
- browser evidence mistaken for backend media truth
- Forger capability escalation
- historical evidence treated as current evidence
- external repository overriding .okf
- resolved conflict removed from final output

## Evaluation

Use deterministic grading for schema validity, source refs, conflict presence, disposition correctness and authority boundaries.

Use trajectory evaluation for role routing and mandatory tool/gate order.

Use deeper judge reasoning only as secondary evidence.

Every benchmark records dataset version, source commit, .okf revision, mapping revisions, model revision and evaluation revision.
