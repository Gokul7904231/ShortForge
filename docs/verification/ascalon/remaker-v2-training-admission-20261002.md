## Scope

This record defines the learning boundary for ReMaker. It does not authorize model-weight training and does not grant production authority.

ReMaker is represented as a bounded repair mechanism under Guardian authorization and Healer coordination:

`F07 finding -> explicit remediation case -> Guardian capability grant -> ReMaker impact analysis -> bounded RenderFabric execution -> physical candidate evidence -> F07 re-verification`

## Training-eligible ReMaker behavior

A trajectory may be admitted only when it shows:

1. An explicit F07/remediation finding and concrete target scope.
2. A Guardian-authorized `CAP_REMAKER_REPAIR` capability.
3. A live lease identity with a monotonic fencing token and expiry.
4. Immutable parent artifact identity and matching TimelineIR provenance.
5. Deterministic requested-change identity.
6. Narrow logical impact plus explicitly derived physical render scenes.
7. Preservation fingerprints for unaffected TimelineIR nodes.
8. Physical renderer evidence from the canonical RenderFabric path.
9. A new candidate artifact, never an unchanged parent artifact.
10. Independent F07 verification before final success.

## Hard-negative curriculum

The curriculum must include rejection examples for:

- unauthorized repair action;
- missing or forged Guardian authorization;
- expired authorization;
- stale fencing token;
- stale or mismatched parent artifact;
- TimelineIR lineage mismatch;
- extra changed nodes;
- missing preserved nodes;
- preservation fingerprint mismatch;
- invalid physical artifact;
- repeated failed/no-progress repair;
- attempts to use ReMaker for upstream semantic/script changes.

## Simulation boundary

Synthetic examples generated by `ScenarioGenerator` are explicitly labeled:

- `environment = SIMULATION`

## Validator boundary

`AscalonTrajectoryValidator` recognizes `CAP_REMAKER_REPAIR` and blocks ReMaker training trajectories that omit authorization, fencing, parent lineage, preservation evidence, or F07 verification evidence.
